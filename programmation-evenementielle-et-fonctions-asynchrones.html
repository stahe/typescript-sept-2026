    11. Programmation événementielle et fonctions asynchrones

    Une fonction asynchrone est une fonction dont l'exécution est lancée mais dont on n'attend pas immédiatement le résultat. Lorsque l'exécution est terminée, la fonction asynchrone signale son résultat — par un événement, ou par une [Promise], comme on le verra plus loin.

    Ce mode de fonctionnement est bien adapté à l'exécution dans un navigateur, où l'application réagit en permanence à des événements (clics, frappe clavier, réponses réseau...). Les scripts de ce chapitre sont exécutés par [node.js], qui utilise lui aussi une boucle d'événements :

    • l'exécution du code principal du script est le 1er événement traité ;
    • si ce code a lancé des tâches asynchrones, l'exécution du script se poursuit tant qu'elles ne sont pas terminées — elles émettent un événement une fois terminées, mis en file d'attente dans la boucle d'événements ;
    • le script principal doit s'abonner à ces événements pour récupérer leurs résultats ;
    • le script ne se termine que lorsque tous les événements qu'il a émis ont été traités.

    Les scripts de ce chapitre se trouvent dans le dossier [async] du projet.

    11.1. script [async-01]

    Ce script montre le comportement d'un script comportant une action asynchrone, à l'aide de la fonction native [setTimeout] :

      1  'use strict';
  2  
  3  // imports
  4  import moment from 'moment';
  5  import { sprintf } from 'sprintf-js';
  6  
  7  // début
  8  const débutScript = moment(Date.now());
  9  console.log("[début du script],", heure());
 10  
 11  // setTimeout arme un timer de 1000 ms (2ième paramètre) et retourne immédiatement le n° de ce timer
 12  // lorsque le timer a épuisé les 1000 ms il émet un événement qui est mis en file d'attente du runtime
 13  // lorsque l'événement est traité par le runtime, la fonction (1er paramètre) est exécutée
 14  setTimeout(function () {
 15    // ce code sera exécuté lorsque le timer aura atteint la valeur 0
 16    console.log("[fin de l'action asynchrone setTimeout],", heure(débutScript));
 17  }, 1000)
 18  
 19  // s'affichera avant le msg de la fonction interne au timer
 20  console.log("[fin du code principal du script],", heure(débutScript));
 21  
 22  // utilitaire d'affichage heure et durée
 23  function heure(début?: moment.Moment): string {
 24    // heure du moment courant
 25    const now = moment(Date.now());
 26    // formatage heure
 27    let result = "heure=" + now.format("HH:mm:ss:SSS");
 28    // faut-il calculer une durée ?
 29    if (début) {
 30      const durée = now.valueOf() - début.valueOf();
 31      const milliseconds = durée % 1000;
 32      const seconds = Math.floor(durée / 1000);
 33      // formatage heure + durée
 34      result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
 35    }
 36    // résultat
 37    return result;
 38  }
    • lignes 14-17 : [setTimeout] admet deux paramètres : une fonction à exécuter, et un délai en millisecondes. Son exécution est instantanée : elle arme un minuteur et rend immédiatement la main, sans attendre la fin du délai ;
    • ligne 19 : ce message s'affiche donc avant celui de la ligne 15, alors qu'il est écrit après dans le code ;
    • ligne 22 : function heure(début?: moment.Moment): string — le paramètre début est optionnel (?), typé moment.Moment ; si fourni, la fonction calcule et ajoute une durée écoulée.
    npx tsx async/async-01.ts

    Résultat de l'exécution :

      1  [début du script], heure=07:41:36:456
  2  [fin du code principal du script], heure=07:41:36:457, durée= 0 seconde(s) et 2 millisecondes
  3  [fin de l'action asynchrone setTimeout], heure=07:41:37:458, durée= 1 seconde(s) et 3 millisecondes

    On observe que l'action asynchrone setTimeout se termine environ 1 seconde après la fin du code principal — c'est bien le délai programmé. Le script global, lui, n'est terminé qu'une fois cette tâche asynchrone achevée.

    Remarque : setTimeout va nous servir à simuler des tâches asynchrones tout au long de ce chapitre. Une vraie tâche asynchrone (requête réseau, lecture de fichier...) se comporte de la même façon : elle rend la main immédiatement, puis signale son résultat plus tard — généralement via deux événements possibles, l'un de succès, l'autre d'échec.

    11.2. script [async-02]

    Ce script montre comment une fonction asynchrone peut communiquer son résultat en émettant des événements, à l'aide de la classe native EventEmitter (module node:events) :

      1  'use strict';
  2  
  3  // les fonctions asynchrones peuvent rendre un résultat en émettant un événement
  4  // le code principal peut récupérer ces résultats en s'abonnant aux événements émis
  5  
  6  // imports
  7  import moment from 'moment';
  8  import { sprintf } from 'sprintf-js';
  9  import EventEmitter from 'events';
 10  
 11  // début
 12  const débutScript = moment(Date.now());
 13  console.log("[début du script],", heure());
 14  // un émetteur d'événements
 15  const eventEmitter = new EventEmitter();
 16  
 17  // setTimeout arme un timer de 1000 ms (2ième paramètre) et retourne immédiatement le n° de ce timer
 18  // lorsque le timer a épuisé les 1000 ms il émet un événement qui est mis en file d'attente du runtime
 19  // lorsque l'événement est traité par le runtime, la fonction (1er paramètre) est exécutée
 20  setTimeout(function () {
 21    // ce code sera exécuté lorsque le timer aura atteint la valeur 0
 22    console.log("[setTimeout, fin du timer d'1 s],", heure(débutScript));
 23    // on émet un événement pour dire qu'un résultat est disponible
 24    eventEmitter.emit("timer1Success", { success: 4 });
 25    // on émet un autre événement pour dire qu'un autre résultat est disponible
 26    eventEmitter.emit("timer1Failure", { failure: 6 });
 27  }, 1000)
 28  
 29  // on s'abonne à l'évt [timer1Success]
 30  eventEmitter.on('timer1Success', (result) => {
 31    console.log(sprintf("la fonction asynchrone du timer a rendu le résultat [%j], %s, via l'événement [timer1Success]", result, heure(débutScript)));
 32  });
 33  
 34  // on s'abonne à l'évt [timer1Failure]
 35  eventEmitter.on('timer1Failure', (result) => {
 36    console.log(sprintf("la fonction asynchrone du timer a rendu le résultat [%j], %s, via l'événement [timer1Failure]", result, heure(débutScript)));
 37  });
 38  
 39  // s'affichera avant les msg des evts émis par la fonction associée à [timer1]
 40  console.log("[fin du code principal du script],", heure(débutScript));
 41  
 42  // utilitaire d'affichage heure et durée
 43  function heure(début?: moment.Moment): string {
 44    // heure du moment courant
 45    const now = moment(Date.now());
 46    // formatage heure
 47    let result = "heure=" + now.format("HH:mm:ss:SSS");
 48    // faut-il calculer une durée ?
 49    if (début) {
 50      const durée = now.valueOf() - début.valueOf();
 51      const milliseconds = durée % 1000;
 52      const seconds = Math.floor(durée / 1000);
 53      // formatage heure + durée
 54      result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
 55    }
 56    // résultat
 57    return result;
 58  }
    • ligne 8 : import EventEmitter from 'events' — importe la classe qui permet d'émettre et d'écouter des événements ;
    • ligne 15 : const eventEmitter = new EventEmitter() — un émetteur d'événements est instancié avec new ;
    • lignes 24 et 26 : la fonction encapsulée dans setTimeout émet deux événements, timer1Success et timer1Failure, chacun avec sa propre donnée associée (ici, à titre de démonstration seulement — normalement une même tâche n'émettrait que l'un ou l'autre) ;
    • lignes 29-37 : le code principal s'abonne à ces deux événements avec eventEmitter.on(nomÉvénement, callback) — le callback ne s'exécutera qu'au moment où l'événement sera réellement émis, pas au moment de l'abonnement ;
    • ligne 40 : le code principal se termine ici, mais le script global ne se termine que lorsque la tâche asynchrone (et les callbacks abonnés) ont fini de s'exécuter.
    npx tsx async/async-02.ts

    Résultat de l'exécution :

      1  [début du script], heure=07:41:38:163
  2  [fin du code principal du script], heure=07:41:38:170, durée= 0 seconde(s) et 7 millisecondes
  3  [setTimeout, fin du timer d'1 s], heure=07:41:39:173, durée= 1 seconde(s) et 10 millisecondes
  4  la fonction asynchrone du timer a rendu le résultat [{"success":4}], heure=07:41:39:173, durée= 1 seconde(s) et 10 millisecondes, via l'événement [timer1Success]
  5  la fonction asynchrone du timer a rendu le résultat [{"failure":6}], heure=07:41:39:173, durée= 1 seconde(s) et 10 millisecondes, via l'événement [timer1Failure]

    11.3. script [async-03]

    La boucle d'événements de node.js n'exécute qu'un seul événement à la fois : le suivant n'est traité qu'une fois le précédent terminé. Un code synchrone qui monopolise longtemps le processeur retarde donc le traitement de tous les événements en attente — y compris ceux déjà émis. Ce script (identique à async-02, avec une boucle intensive ajoutée) le démontre :

      1  'use strict';
  2  
  3  // les fonctions asynchrones peuvent rendre un résultat en émettant un événement
  4  // le code principal peut récupérer ces résultats en s'abonnant aux événements émis
  5  
  6  // imports
  7  import moment from 'moment';
  8  import { sprintf } from 'sprintf-js';

 13  console.log("[début du script],", heure());
 14  // un émetteur d'événements
 15  const eventEmitter = new EventEmitter();
 16  
 17  // setTimeout arme un timer de 1000 ms (2ième paramètre) et retourne immédiatement le n° de ce timer
 18  // lorsque le timer a épuisé les 1000 ms il émet un événement qui est mis en file d'attente du runtime
 19  // lorsque l'événement est traité par le runtime, la fonction (1er paramètre) est exécutée
 20  setTimeout(function () {
 21    // ce code sera exécuté lorsque le timer aura atteint la valeur 0
 22    console.log("[setTimeout, fin du timer d'1 s],", heure(débutScript));
 23    // on émet un événement pour dire qu'un résultat est disponible
 24    eventEmitter.emit("timer1Success", { success: 4 });
 25    // on émet un autre événement pour dire qu'un autre résultat est disponible
 26    eventEmitter.emit("timer1Failure", { failure: 6 });
 27  }, 1000)
 28

 31    console.log(sprintf("la fonction asynchrone du timer a rendu le résultat [%j], %s, via l'événement [timer1Success]", result, heure(débutScript)));
 32  });
 33  
 34  // on s'abonne à l'évt [timer1Failure]
 35  eventEmitter.on('timer1Failure', (result) => {
 36    console.log(sprintf("la fonction asynchrone du timer a rendu le résultat [%j], %s, via l'événement [timer1Failure]", result, heure(débutScript)));
 37  });
 38  
 39  // un code synchrone un peu intensif qui a empêcher le code principal de s'achever avant la fin de [timer1]

    • le timer d'1 seconde a fini son délai bien avant la fin de cette boucle — mais l'événement qu'il a émis doit attendre que le code synchrone rende la main à la boucle d'événements pour être enfin traité.

      1  [début du script], heure=07:41:39:891
  2  [fin du code principal du script], heure=07:41:45:623, durée= 5 seconde(s) et 732 millisecondes
  3  [setTimeout, fin du timer d'1 s], heure=07:41:45:625, durée= 5 seconde(s) et 734 millisecondes

  5  la fonction asynchrone du timer a rendu le résultat [{"failure":6}], heure=07:41:45:625, durée= 5 seconde(s) et 734 millisecondes, via l'événement [timer1Failure]

    Le code principal a mis environ 5,7 secondes à s'exécuter (durée variable selon la machine), alors que le timer avait fini son délai d'une seconde depuis longtemps : l'événement associé a dû patienter que la boucle synchrone se termine. On retiendra qu'un code synchrone long doit, autant que possible, être décomposé en tâches asynchrones plus courtes.

    11.4. Le mécanisme Promise

    Le type [Promise] est une classe qui évite de gérer explicitement des événements : c'est fait implicitement, mais comprendre les événements sous-jacents aide à mieux appréhender son fonctionnement. Son constructeur admet en paramètre une fonction asynchrone à qui il transmet deux fonctions, traditionnellement nommées [resolve] et [reject] :

    const promise = new Promise(function (resolve, reject) {
  // une tâche asynchrone est lancée
  // ...
  // si réussite : appeler resolve(result) où [result] est le résultat de la tâche
  // si échec : appeler reject(error) où [error] encapsule l'erreur rencontrée
});

    Un objet Promise peut être dans quatre états :

    • [pending] : la tâche asynchrone n'est pas encore terminée ;
    • [fulfilled] : elle s'est terminée avec succès ;
    • [rejected] : elle s'est terminée sur un échec ;
    • [settled] : elle est terminée (succès ou échec, peu importe).

    On s'abonne aux résultats d'une Promise avec la syntaxe promise.then(f1).catch(f2).finally(f3) : f1 s'exécute en cas de succès (elle reçoit le résultat transmis par resolve), f2 en cas d'échec (elle reçoit l'erreur transmise par reject), f3 dans tous les cas, sans paramètre.

    11.5. script [async-04]

    Ce script crée deux Promise indépendantes, chacune encapsulant un setTimeout, et s'abonne à leurs résultats :

      1  'use strict';
  2  
  3  // il est possible d'obtenir les résultats (success, failure) d'une fonction asynchrone
  4  // sans utiliser explicitement des événements grâce à la classe [Promise]
  5  // cette classe utilise implicitement des événements mais ceux-ci ne se voient pas dans le code
  6  
  7  // imports
  8  import moment from 'moment';
  9  import { sprintf } from 'sprintf-js';
 10  
 11  // début
 12  const débutScript = moment(Date.now());
 13  console.log("[début du script],", heure(débutScript));
 14  
 15  // définition d'une tâche asynchrone à l'aide d'une promesse [Promise]
 16  // la tâche asynchrone est le paramètre du constructeur [Promise]
 17  const débutPromise1 = moment(Date.now());
 18  const promise1 = new Promise<string>(function (resolve) {
 19    // log
 20    console.log("[début fonction asynchrone de promise1],", heure(débutPromise1));
 21    // code asynchrone
 22    setTimeout(function () {
 23      // ce code est exécuté après un délai d'1 seconde (2ième paramètre)
 24      console.log("[fin fonction asynchrone de promise1],", heure(débutPromise1));
 25      // la tâche asynchrone rend un résultat avec la fonction [resolve]
 26      // la promesse est alors réussie
 27      resolve('[réussite]');
 28    }, 1000)
 29  });
 30  
 31  // on peut connaître le résultat de la promesse [promise1]
 32  // lorsque celle-ci a été résolue (resolve) ou rejetée (reject)
 33  // l'instruction qui suit est un abonnement à l'évt [resolved] via la méthode [then]
 34  // et à l'évt [rejected] via la méthode [catch]
 35  // la méthode [finally] est exécutée que ce soit après un then ou un catch
 36  promise1.then(result => {
 37    // cas de réussite de la promesse  [evt resolved]
 38    console.log(sprintf("[promise1.then], %s, result=%s", heure(débutPromise1), result));
 39  }).catch(result => {
 40    // cas d'erreur  [evt rejected]
 41    console.log(sprintf("[promise1.catch], %s, result=%s", heure(débutPromise1), result));
 42  }).finally(() => {
 43    // exécuté dans tous les cas
 44    console.log("[promise1.finally]", heure(débutPromise1));
 45  });
 46  
 47  // définition d'une tâche asynchrone à l'aide d'une promesse [Promise]
 48  const débutPromise2 = moment(Date.now());
 49  const promise2 = new Promise<string>(function (resolve, reject) {
 50    // log
 51    console.log("[début fonction asynchrone de promise2],", heure(débutPromise2));
 52    // tâche asynchrone
 53    setTimeout(function () {
 54      console.log("[fin fonction asynchrone de promise2],", heure(débutPromise2));
 55      // la tâche asynchrone rend un résultat avec la fonction [reject]
 56      // la promesse est alors ratée
 57      reject('[échec]');
 58    }, 2000)
 59  });
 60  
 61  // on peut connaître le résultat de la promesse [promise2]
 62  // lorsque celle-ci a été résolue (resolve) ou rejetée (reject)
 63  promise2.then(result => {
 64    // cas de réussite de la promesse [evt resolved]
 65    console.log(sprintf("[promise2.then], %s, result=%s", heure(débutPromise2), result));
 66  }).catch(result => {
 67    // cas d'erreur [evt rejected]
 68    console.log(sprintf("[promise2.catch], %s, result=%s", heure(débutPromise2), result));
 69  }).finally(() => {
 70    // exécuté dans tous les cas
 71    console.log(sprintf("[promise2.finally], %s", heure(débutPromise2)));
 72  });
 73  
 74  // s'affichera avant les msg des fonctions asynchrones et ceux des évts associés
 75  console.log("[fin du code principal du script],", heure(débutScript));
 76  
 77  // utilitaire
 78  function heure(début?: moment.Moment): string {
 79    // heure du moment courant
 80    const now = moment(Date.now());
 81    // formatage heure
 82    let result = "heure=" + now.format("HH:mm:ss:SSS");
 83    if (début) {
 84      const durée = now.valueOf() - début.valueOf();
 85      const milliseconds = durée % 1000;
 86      const seconds = Math.floor(durée / 1000);
 87      // formatage durée
 88      result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
 89    }
 90    // résultat
 91    return result;
 92  }
    • ligne 20 : new Promise<string>(function (resolve) {...}) — TypeScript permet de préciser, via le paramètre générique <string>, le type de la valeur que resolve transmettra ; sans lui, ce type serait déduit unknown ;
    • promise1 se résout avec succès après 1 seconde (resolve('[réussite]')) ; promise2 échoue après 2 secondes (reject('[échec]')) ;
    • le code principal (ligne 78) se termine bien avant que les deux promesses aient un résultat — le script global, lui, continue jusqu'à ce qu'elles soient toutes deux réglées (*settled*).
    npx tsx async/async-04.ts

    Résultat de l'exécution :

  2  [début fonction asynchrone de promise1], heure=07:42:29:443, durée= 0 seconde(s) et 0 millisecondes
  3  [début fonction asynchrone de promise2], heure=07:42:29:444, durée= 0 seconde(s) et 0 millisecondes

  9  [promise2.catch], heure=07:42:31:446, durée= 2 seconde(s) et 2 millisecondes, result=[échec]

    11.6. script [async-05]

    On définit le plus souvent une fonction asynchrone rendant une Promise, plutôt que de créer directement l'objet Promise — pratique quand elle a besoin de paramètres. Ce script définit deux fonctions asynchrones et attend qu'elles se terminent toutes les deux avec [Promise.all] :

      1  'use strict';
  2  
  3  // on peut définir des fonctions asynchrones qui rendent un type [Promise]
  4  // elles peuvent être alors taguées avec le mot clé [async]
  5  // là encore
  6  // imports
  7  import moment from 'moment';
  8  import { sprintf } from 'sprintf-js';
  9  
 10  // début
 11  const débutScript = moment(Date.now());
 12  console.log("[début du script],", heure());
 13  
 14  // forme du résultat rendu par async01 et async02
 15  interface RésultatAsync {
 16    prop1: number[];
 17    prop2: string;
 18    prop3: number;
 19  }
 20  
 21  // une fonction asynchrone peut rendre une promesse [Promise]
 22  // et avoir alors l'attribut [async]
 23  async function async01(p1: number): Promise<RésultatAsync> {
 24    return new Promise<RésultatAsync>(resolve => {
 25      console.log("[début de la tâche asynchrone async01]");
 26      // la tâche asynchrone
 27      const débutAsync01 = moment(Date.now());
 28      setTimeout(function () {
 29        // ce code est exécuté après un délai d'1 seconde (2ième paramètre)
 30        console.log("[fin de la tâche asynchrone async01],", heure(débutAsync01));
 31        // la tâche asynchrone peut rendre un résultat complexe
 32        resolve({
 33          prop1: [10, 20, 30],
 34          prop2: "abcd",
 35          prop3: p1,
 36        });
 37      }, 1000)
 38    });
 39  }
 40  
 41  // une fonction peut rendre une promesse [Promise]
 42  // et peut alors avoir l'attribut [async]
 43  async function async02(p1: number, p2: number): Promise<RésultatAsync> {
 44    return new Promise<RésultatAsync>(resolve => {
 45      console.log("[début de la tâche asynchrone async02]");
 46      // tâche asynchrone
 47      const débutAsync02 = moment(Date.now());
 48      setTimeout(function () {
 49        // le code suivant est exécuté après un délai de 2 secondes (2ième paramètre)
 50        console.log("[fin de la tâche asynchrone async02],", heure(débutAsync02));
 51        // la tâche asynchrone peut rendre un résultat complexe
 52        resolve({
 53          prop1: [11, 21, 31],
 54          prop2: "xyzt",
 55          prop3: p1 + p2
 56        });
 57      }, 2000)
 58    })
 59  }
 60  
 61  // on lance les deux fonctions asynchrones en parallèle
 62  // et on attend qu'elles aient terminé toutes les deux
 63  // le then ne s'exécutera que si les deux fonctions ont émis l'évt [resolved]
 64  // le catch s'exécutera dès que l'une des deux fonctions émet l'évt [rejected]
 65  Promise.all([async01(10), async02(10, 20)])
 66    // le résultat est un tableau [result1, result2] où [result1] est le résultat émis par un [resolve] de [async01]
 67    // et [result2] le résultat émis par un [resolve] de [async02]
 68    .then(result => {
 69      console.log(sprintf("[promise-all success], %s, result=%j", heure(débutScript), result));
 70    })
 71    // error est le résultat émis par le premier [reject] de l'une des deux fonctions asynchrones
 72    .catch(error => {
 73      console.log(sprintf("[promise-all error], %s, erreur=%j", heure(débutScript), error));
 74    })
 75    // finally est exécuté après le then ou le catch
 76    .finally(() => {
 77      console.log(sprintf("[promise-all finally], %s", heure(débutScript)));
 78    });
 79  
 80  // s'affichera avant les msgs des fonctions asynchrones et des évts associés
 81  console.log("[fin du code principal du script],", heure(débutScript));
 82  
 83  // utilitaire
 84  function heure(début?: moment.Moment): string {
 85    // heure du moment courant
 86    const now = moment(Date.now());
 87    // formatage heure
 88    let result = "heure=" + now.format("HH:mm:ss:SSS");
 89    if (début) {
 90      const durée = now.valueOf() - début.valueOf();
 91      const milliseconds = durée % 1000;
 92      const seconds = Math.floor(durée / 1000);
 93      // formatage durée
 94      result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
 95    }
 96    // résultat
 97    return result;
 98  }
    • lignes 20 et 36 : les fonctions asynchrones sont typées Promise<RésultatAsync> grâce à l'interface RésultatAsync définie plus haut ;
    • ligne 62 : [Promise.all([...])] attend que toutes les promesses du tableau soient résolues avant d'exécuter son then — dès que l'une échoue, son catch s'exécute immédiatement, sans attendre les autres ;
    • les deux tâches se déroulent en parallèle (leurs attentes respectives se chevauchent) : la durée totale (~2s) correspond à la plus longue des deux, pas à leur somme (~3s).

    11.7. script [async-06] — async / await

    Les mots clés [async]/[await] permettent d'écrire du code asynchrone qui ressemble à du code synchrone : la gestion des événements sous-jacents est complètement cachée, ce qui facilite grandement la lecture. Ce script définit trois fonctions asynchrones — la 3ᵉ échoue volontairement — et les exécute d'abord séquentiellement, puis en parallèle :

      1  'use strict';
  2  
  3  // exécution parallèle ou séquentielle de plusieurs tâches asynchrones
  4  // avec les mots clés async / await
  5  
  6  // imports
  7  import moment from 'moment';
  8  import { sprintf } from 'sprintf-js';
  9  
 10  // début
 11  const débutScript = moment(Date.now());
 12  console.log("[début du code principal du script],", heure());
 13  
 14  // forme du résultat rendu par async01/async02/async03
 15  interface RésultatAsync {
 16    prop1: number[];
 17    prop2: string;
 18  }
 19  
 20  // une fonction asynchrone rendant une [Promise]
 21  async function async01(débutAsync01: moment.Moment): Promise<RésultatAsync> {
 22    return new Promise(function (resolve) {
 23      console.log("[début fonction asynchrone async01],", heure());
 24      // fonction asynchrone
 25      setTimeout(function () {
 26        console.log("[fin fonction asynchrone async01],", heure(débutAsync01));
 27        // l'action asynchrone peut rendre un résultat complexe
 28        // ici réussite
 29        resolve({
 30          prop1: [11, 21, 31],
 31          prop2: "abcd"
 32        });
 33      }, 1000)
 34    });
 35  }

 66        });
 67      }, 3000)
 68    })
 69  }

 71  // fonction asynchrone - utilisation async / await
 72  async function main(): Promise<void> {
 73    const débutSequential = moment(Date.now());
 74    // exécution séquentielle des tâches asynchrones
 75    console.log("------------ exécution séquentielle des tâches asynchrones lancée ------------------------")
 76    try {
 77      // exécution avec attente de [async01]
 78      const débutAsync01 = moment(Date.now());
 79      const result1 = await async01(débutAsync01);
 80      console.log("[async01 result]=", result1);
 81      // exécution avec attente de [async02]
 82      const débutAsync02 = moment(Date.now());
 83      console.log("début async02-------------", heure());
 84      const result2 = await async02(débutAsync02);
 85      console.log("[async02 result]=", result2);
 86      // exécution avec attente de [async03]
 87      const débutAsync03 = moment(Date.now());
 88      console.log("début async03-------------", heure());
 89      const result3 = await async03(débutAsync03);
 90      console.log("[async03 result]=", result3);
 91    } catch (error) {
 92      // une des actions asynchrones a échoué
 93      console.log(sprintf("[sequential error]= %j, %s", error, heure(débutSequential)));
 94    } finally {
 95      // terminé
 96      console.log("[fin exécution séquentielle des tâches asynchrones],", heure(débutSequential));
 97    }
 98  
 99    const débutParallel = moment(Date.now());
100    // exécution en parallèle des tâches asynchrones
101    console.log("------------ exécution parallèle des tâches asynchrones lancée ------------------------");
102    try {
103      const result = await Promise.all([async01(débutParallel), async02(débutParallel), async03(débutParallel)]);
104      console.log(sprintf("[parallel success], %s, result=%j", heure(débutParallel), result));
105    } catch (error) {
106      // une des actions asynchrones a échoué
107      console.log(sprintf("[parallel error], %s, erreur=%j", heure(débutParallel), error));
108    } finally {
109      // terminé
110      console.log(sprintf("[fin exécution parallèle des tâches asynchrones],%s", heure(débutParallel)));
111    }
112  
113    // terminé
114    console.log("[fin de la fonction main],", heure(débutSequential));
115  }

117  main();

    • ligne 87 : await async01(débutAsync01) suspend l'exécution de main jusqu'à ce que la promesse soit résolue, sans bloquer le reste du programme (le await ne peut s'utiliser qu'à l'intérieur d'une fonction async, ou au premier niveau d'un module — voir chapitre « Les modules », script import-04) ;
    • lignes 85-100 : exécution séquentielle — chaque await attend la fin de la tâche précédente avant de lancer la suivante ; la durée totale est la somme des trois délais (~6s) ;
    • lignes 106-113 : exécution en parallèle, avec await Promise.all([...]) — la durée totale est celle de la tâche la plus longue (~3s) ;
    • un try/catch classique suffit à intercepter l'échec d'une promesse await-ée — plus besoin de .catch() chaîné comme aux scripts précédents.

    11.8. script [async-07] — compléments à Promise

    [NOUVEAU depuis 2019] Ce script présente quatre compléments apparus entre 2020 et 2024, aujourd'hui très utilisés en TypeScript moderne :

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU depuis 2019] compléments à la classe Promise
  4  // ========================================================================
  5  
  6  // petite fonction utilitaire : renvoie une promesse qui réussit ou échoue après [délai] ms
  7  function tâche(nom: string, délai: number, réussit: boolean): Promise<string> {
  8    return new Promise<string>((resolve, reject) => {
  9      setTimeout(() => {
 10        if (réussit) {
 11          resolve(`résultat de ${nom}`);
 12        } else {
 13          reject(`échec de ${nom}`);
 14        }
 15      }, délai);
 16    });
 17  }
 18  
 19  // ------------------------------------------------------------------------
 20  // 1) Promise.allSettled()  (ECMAScript 2020)
 21  // ------------------------------------------------------------------------
 22  // async-05.js montre Promise.all() : si UNE des promesses échoue, le catch est déclenché
 23  // et on perd le résultat des autres promesses qui, elles, avaient réussi
 24  // Promise.allSettled() attend TOUJOURS que toutes les promesses soient terminées
 25  // (réussies ou en échec) et rend le détail de chacune, sans jamais rejeter
 26  async function démoAllSettled(): Promise<void> {
 27    console.log("--- Promise.allSettled ---");
 28    const résultats = await Promise.allSettled([
 29      tâche("tâche1", 300, true),
 30      tâche("tâche2", 200, false),
 31      tâche("tâche3", 100, true)
 32    ]);
 33    // chaque élément a la forme { status: "fulfilled", value: ... } ou { status: "rejected", reason: ... }
 34    résultats.forEach((résultat, index) => {
 35      if (résultat.status === "fulfilled") {
 36        console.log(`tâche${index + 1} réussie :`, résultat.value);
 37      } else {
 38        console.log(`tâche${index + 1} échouée :`, résultat.reason);
 39      }
 40    });
 41  }
 42  
 43  // ------------------------------------------------------------------------
 44  // 2) Promise.any()  (ECMAScript 2021)
 45  // ------------------------------------------------------------------------
 46  // rend le résultat de la PREMIÈRE promesse qui réussit (les autres sont ignorées)
 47  // ne rejette que si TOUTES les promesses échouent (avec une AggregateError regroupant les erreurs)
 48  async function démoAny(): Promise<void> {
 49    console.log("--- Promise.any ---");
 50    try {
 51      const résultat = await Promise.any([
 52        tâche("miroir-lent", 500, true),
 53        tâche("miroir-rapide", 100, true),
 54        tâche("miroir-en-panne", 50, false)
 55      ]);
 56      console.log("premier miroir disponible :", résultat);
 57    } catch (erreurGlobale: any) {
 58      // erreurGlobale.errors contient la liste de toutes les erreurs individuelles
 59      console.log("tous les miroirs ont échoué :", erreurGlobale.errors);
 60    }
 61  }
 62  
 63  // ------------------------------------------------------------------------
 64  // 3) Promise.withResolvers()  (ECMAScript 2024)
 65  // ------------------------------------------------------------------------
 66  // avant, pour "sortir" les fonctions resolve/reject du constructeur Promise
 67  // (par ex. pour les appeler bien plus tard, ailleurs dans le code), il fallait
 68  // une variable intermédiaire un peu artificielle :
 69  //   let resolveExterne;
 70  //   const promesse = new Promise(resolve => { resolveExterne = resolve; });
 71  // Promise.withResolvers() fait ça directement, en une seule expression
 72  function démoWithResolvers(): Promise<string> {
 73    console.log("--- Promise.withResolvers ---");
 74    const { promise, resolve } = Promise.withResolvers<string>();
 75  
 76    // on peut résoudre la promesse depuis n'importe où, par exemple dans un autre callback
 77    setTimeout(() => {
 78      console.log("[callback externe] on déclenche la résolution de la promesse");
 79      resolve("valeur transmise depuis un callback externe");
 80    }, 200);
 81  
 82    return promise;
 83  }
 84  
 85  // ------------------------------------------------------------------------
 86  // 4) annuler une opération asynchrone avec AbortController
 87  // ------------------------------------------------------------------------
 88  // AbortController permet d'annuler une opération asynchrone en cours (fetch, timers, ...)
 89  // c'est le mécanisme standard utilisé par [fetch] pour les délais d'attente (cf http/fetch-01.js)
 90  function tâcheAnnulable(délai: number, signal: AbortSignal): Promise<string> {
 91    return new Promise<string>((resolve, reject) => {
 92      const timer = setTimeout(() => resolve("terminé normalement"), délai);
 93      // si le signal d'annulation est déclenché, on arrête tout et on rejette
 94      signal.addEventListener("abort", () => {
 95        clearTimeout(timer);
 96        reject(new Error("opération annulée : " + signal.reason));
 97      });
 98    });
 99  }

101  async function démoAbortController(): Promise<void> {
102    console.log("--- AbortController ---");
103    const contrôleur = new AbortController();
104    // on programme l'annulation dans 100 ms, avant la fin normale de la tâche (500 ms)
105    setTimeout(() => contrôleur.abort("délai dépassé côté utilisateur"), 100);
106    try {
107      const résultat = await tâcheAnnulable(500, contrôleur.signal);
108      console.log("résultat =", résultat);
109    } catch (erreur: any) {
110      console.log("erreur :", erreur.message);
111    }
112  }
113  
114  // exécution successive des démonstrations
115  async function main(): Promise<void> {
116    await démoAllSettled();
117    await démoAny();
118    console.log("--- Promise.withResolvers, résultat ---", await démoWithResolvers());
119    await démoAbortController();
120  }

    • [Promise.any] (ES2021) : rend le résultat de la première promesse qui réussit, en ignorant les autres — ne rejette que si toutes échouent ;
    • [Promise.withResolvers] (ES2024) : extrait resolve et reject du constructeur Promise en une seule expression, utile pour résoudre une promesse plus tard, depuis un autre endroit du code ;
    • [AbortController] : permet d'annuler une opération asynchrone en cours — c'est le mécanisme standard utilisé par fetch pour les délais d'attente (voir chapitre « Les fonctions HTTP »).
