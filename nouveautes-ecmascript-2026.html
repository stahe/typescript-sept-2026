    16. Nouveautés ECMAScript 2026

    ECMAScript 2026 (17ème édition du langage) a été officiellement finalisé par TC39 en 2026. D'après le texte officiel de la spécification (https://tc39.es/ecma262/2026/), cette édition a ajouté : Math.sumPrecise pour additionner un ensemble de nombres en minimisant la perte de précision ; Iterator.concat pour enchaîner des itérateurs ; Array.fromAsync (déjà présenté au chapitre précédent) ; Error.isError pour identifier de façon fiable les objets d'erreur ; des méthodes sur Map.prototype et WeakMap.prototype pour fournir une valeur par défaut lors d'une lecture ; des méthodes sur Uint8Array pour les conversions hexadécimale et base64 ; un paramètre context pour les revivers de JSON.parse ; et JSON.rawJSON pour contrôler finement la sortie de JSON.stringify.

    16.1. ⚠️ Un avertissement important, avant de commencer

    Le Stage 4 de TC39 garantit que le comportement d'une fonctionnalité ne changera plus, mais ne garantit pas sa disponibilité immédiate dans tous les moteurs JavaScript. En préparant ce chapitre, un fait concret l'a bien montré : [Math.sumPrecise] provoque une erreur TypeError: Math.sumPrecise is not a function, y compris sur des versions récentes de Node.js. Ce n'est pas un bug de ce cours : V8 (le moteur de Node et Chrome) n'a, à ce jour, tout simplement pas encore implémenté cette fonctionnalité — contrairement à Firefox, Safari et Bun, qui l'ont déjà (source : ticket officiel du dépôt TypeScript, github.com/microsoft/TypeScript/issues/63427).

    C'est pourquoi chaque script de ce chapitre vérifie lui-même, avec typeof, si la fonctionnalité qu'il illustre est disponible avant de l'utiliser, et affiche un message clair sinon — plutôt que de planter brutalement. C'est une bonne pratique en soi lorsqu'on utilise des fonctionnalités très récentes du langage.

    Important : les scripts de ce chapitre ont tous été réellement exécutés dans l'environnement de préparation de ce cours (Node.js 22) ; certains y affichent le message « non disponible », ce qui est un résultat authentique et non une supposition. Sur ta machine, avec une version de Node.js différente, certains de ces scripts pourront afficher un résultat réel plutôt que ce message — n'hésite pas à comparer.

    16.2. script [01-math-sumPrecise]

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU ECMAScript 2026] Math.sumPrecise()
  4  // ========================================================================
  5  // [mise à jour] au moment où ce script est écrit, V8 (donc node et Chrome)
  6  // n'implémente PAS ENCORE Math.sumPrecise, alors que Firefox, Safari et Bun
  7  // l'ont déjà. C'est un exemple concret du décalage qui peut exister entre
  8  // "la fonctionnalité est entrée dans la spécification officielle du langage"
  9  // et "tous les moteurs JavaScript l'ont réellement implémentée" : le Stage 4
 10  // de TC39 (obtenu le 28/07/2025 pour cette fonctionnalité) garantit que le
 11  // comportement ne changera plus, mais ne garantit PAS une disponibilité
 12  // immédiate partout. Voir ecmascript-2026/README.md pour les détails et les
 13  // sources.
 14  // Pour vérifier toi-même si TON node a déjà cette fonctionnalité :
 15  //   node -e "console.log(typeof Math.sumPrecise)"
 16  
 17  // additionner des nombres flottants avec + accumule des erreurs d'arrondi,
 18  // car chaque nombre est représenté en binaire de façon imprécise
 19  const nombres: number[] = [0.1, 0.2, 0.3, 0.1, 0.2, 0.3, 0.1, 0.2, 0.3, 0.1];
 20  
 21  // ------------------------------------------------------------------------
 22  // 1) l'ancienne façon, avec reduce() : le résultat n'est pas exact
 23  // ------------------------------------------------------------------------
 24  const sommeAvecReduce = nombres.reduce((accumulateur, valeur) => accumulateur + valeur, 0);
 25  console.log("somme avec reduce =", sommeAvecReduce);
 26  // on s'attend à 1.9 exactement, mais le résultat contient souvent des décimales parasites
 27  // (ex: 1.9000000000000001) à cause des erreurs d'arrondi qui s'accumulent au fil des additions
 28  
 29  // ------------------------------------------------------------------------
 30  // 2) Math.sumPrecise() : additionne tous les nombres de façon exacte
 31  // ------------------------------------------------------------------------
 32  // contrairement à une boucle d'additions successives, l'algorithme utilisé en interne
 33  // évite d'accumuler les erreurs d'arrondi intermédiaires
 34  if (typeof Math.sumPrecise === "function") {
 35    const sommePrécise = Math.sumPrecise(nombres);
 36    console.log("somme avec Math.sumPrecise =", sommePrécise);
 37  } else {
 38    // on évite ici un plantage brutal (TypeError) pour rester pédagogique :
 39    // ce message s'affichera tant que ton moteur JavaScript n'a pas encore
 40    // implémenté cette fonctionnalité pourtant déjà finalisée dans la spec
 41    console.log("Math.sumPrecise n'est pas encore disponible sur ce moteur JavaScript",
 42      "(voir le commentaire en tête de ce fichier)");
 43  }
 44  
 45  // ------------------------------------------------------------------------
 46  // pourquoi c'est utile : calculs financiers, comptables, scientifiques -
 47  // partout où une petite erreur d'arrondi répétée peut devenir un vrai bug
 48  // (ex : un total de facture qui ne tombe jamais juste au centime près)
 49  // ------------------------------------------------------------------------

  2  Math.sumPrecise n'est pas encore disponible sur ce moteur JavaScript (voir le commentaire en tête de ce fichier)

    16.3. script [02-iterator-concat]

    [Iterator.concat] enchaîne plusieurs itérables (tableau, Set, générateur...) en un seul itérateur paresseux (*lazy*) : les éléments ne sont produits qu'au fur et à mesure, sans construire de collection intermédiaire complète — contrairement à l'opérateur de spread [...a, ...b], qui recopie tout immédiatement en mémoire.

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU ECMAScript 2026] Iterator.concat()
  4  // ========================================================================
  5  // [Node 26+ - officiellement listé dans les notes de version de node 26.0.0 :
  6  // voir https://nodejs.org/en/blog/release/v26.0.0 - donc normalement déjà
  7  // disponible si tu es sur node 26. Si ce n'est pas le cas, vérifie avec :
  8  //   node -e "console.log(typeof Iterator.concat)"
  9  // voir aussi ecmascript-2026/README.md pour le cas des autres nouveautés de
 10  // ce dossier, qui n'ont pas toutes le même niveau de disponibilité]
 11  
 12  // on a parfois plusieurs sources de données à parcourir l'une après l'autre
 13  // (par exemple : plusieurs tableaux, ou un tableau puis un Set, ...)
 14  const premièreVague: string[] = ["Ana", "Léo"];
 15  const deuxièmeVague: Set<string> = new Set(["Nora", "Théo"]);
 16  const troisièmeVague: string[] = ["Zoé"];
 17  
 18  // ------------------------------------------------------------------------
 19  // 1) l'ancienne façon : il fallait tout regrouper dans un nouveau tableau
 20  // ------------------------------------------------------------------------
 21  const tousLesInvitésTableau: string[] = [...premièreVague, ...deuxièmeVague, ...troisièmeVague];
 22  console.log("avec spread :", tousLesInvitésTableau);
 23  // inconvénient : ceci crée un nouveau tableau EN MÉMOIRE avec tous les éléments recopiés,
 24  // même si on n'a besoin que des 2 premiers (ex: pour un affichage paginé)
 25  
 26  // ------------------------------------------------------------------------
 27  // 2) Iterator.concat() : enchaîne les itérables sans les recopier d'abord
 28  // ------------------------------------------------------------------------
 29  // Iterator.concat accepte n'importe quel type d'itérable (tableau, Set, Map, générateur...)
 30  // et rend un itérateur "paresseux" (lazy) : les éléments ne sont produits qu'au fur et à mesure
 31  if (typeof Iterator.concat === "function") {
 32    const tousLesInvités = Iterator.concat(premièreVague, deuxièmeVague, troisièmeVague);
 33  
 34    console.log("-----------------------");
 35    for (const invité of tousLesInvités) {
 36      console.log("invité =", invité);
 37    }
 38  
 39    // ------------------------------------------------------------------------
 40    // avantage du caractère "paresseux" : on peut s'arrêter en cours de route
 41    // sans avoir payé le coût de construire une collection complète à l'avance
 42    // ------------------------------------------------------------------------
 43    const troisPremiers = Iterator.concat(premièreVague, deuxièmeVague, troisièmeVague)
 44      .take(3)
 45      .toArray();
 46    console.log("trois premiers invités =", troisPremiers);
 47  } else {
 48    console.log("Iterator.concat n'est pas disponible sur ce moteur JavaScript",
 49      "(voir le commentaire en tête de ce fichier)");
 50  }

    npx tsx ecmascript-2026/02-iterator-concat.ts

    Résultat de l'exécution :

      1  avec spread : [ 'Ana', 'Léo', 'Nora', 'Théo', 'Zoé' ]
  2  Iterator.concat n'est pas disponible sur ce moteur JavaScript (voir le commentaire en tête de ce fichier)

    16.4. script [03-error-isError]

    [Error.isError] détecte de façon fiable si une valeur est une erreur, y compris lorsqu'elle provient d'un autre « royaume » JavaScript (un contexte d'exécution isolé — une iframe, un worker, ou le module vm de node) : chaque royaume a sa propre classe Error, ce qui met instanceof Error en défaut, comme le script le démontre concrètement :

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU ECMAScript 2026] Error.isError()
  4  // ========================================================================
  5  // [statut de disponibilité à vérifier toi-même : voir ecmascript-2026/README.md.
  6  // Certaines nouveautés d'ES2026 (comme Math.sumPrecise) sont encore absentes
  7  // de V8 malgré le Stage 4 obtenu - il n'est pas exclu que ce soit aussi le cas
  8  // ici. Vérifie avec : node -e "console.log(typeof Error.isError)"]
  9  
 10  // jusqu'ici, pour savoir si une valeur est une erreur, on utilisait [instanceof Error]
 11  // (cf. exceptions/excep-03.ts) - cela fonctionne bien... sauf dans certains cas piégeux
 12  
 13  // ------------------------------------------------------------------------
 14  // 1) le piège de [instanceof] avec plusieurs "royaumes" JavaScript
 15  // ------------------------------------------------------------------------
 16  // un "royaume" (realm) est un contexte d'exécution JavaScript isolé : par exemple,
 17  // une iframe dans un navigateur, un worker, ou le module [vm] de node qui permet
 18  // d'exécuter du code dans un contexte séparé. Chaque royaume a SA PROPRE classe [Error],
 19  // distincte de celle du royaume principal.
 20  import vm from 'node:vm';
 21  
 22  // on exécute "new Error('venue d'ailleurs')" dans un royaume séparé
 23  const erreurDunAutreRoyaume: unknown = vm.runInNewContext("new Error('venue d\\'ailleurs')");
 24  
 25  console.log("erreurDunAutreRoyaume =", erreurDunAutreRoyaume);
 26  // [instanceof Error] échoue ici : ce n'est PAS la même classe [Error] que la nôtre,
 27  // même si l'objet EST bien, conceptuellement, une erreur
 28  console.log("erreurDunAutreRoyaume instanceof Error :", erreurDunAutreRoyaume instanceof Error);
 29  
 30  // ------------------------------------------------------------------------
 31  // 2) Error.isError() : détection fiable, même entre royaumes différents
 32  // ------------------------------------------------------------------------
 33  if (typeof Error.isError === "function") {
 34    console.log("Error.isError(erreurDunAutreRoyaume) :", Error.isError(erreurDunAutreRoyaume));
 35  
 36    // pour comparaison, sur une erreur "normale" (même royaume), les deux façons de faire
 37    // donnent le même résultat
 38    const erreurNormale = new Error("erreur classique");
 39    console.log("erreurNormale instanceof Error :", erreurNormale instanceof Error);
 40    console.log("Error.isError(erreurNormale) :", Error.isError(erreurNormale));
 41  
 42    // et sur une valeur qui n'est clairement pas une erreur
 43    console.log("Error.isError('abc') :", Error.isError("abc"));
 44    console.log("Error.isError(null) :", Error.isError(null));
 45  } else {
 46    console.log("Error.isError n'est pas disponible sur ce moteur JavaScript",
 47      "(voir le commentaire en tête de ce fichier) - mais le piège avec [instanceof]",
 48      "démontré ci-dessus, lui, est bien réel et déjà observable");
 49  }

    npx tsx ecmascript-2026/03-error-isError.ts

    Résultat de l'exécution :

      1  erreurDunAutreRoyaume = Error: venue d'ailleurs
  2      at evalmachine.<anonymous>:1:1
  3  erreurDunAutreRoyaume instanceof Error : false
  4  Error.isError n'est pas disponible sur ce moteur JavaScript (voir le commentaire en tête de ce fichier) - mais le piège avec [instanceof] démontré ci-dessus, lui, est bien réel et déjà observable

    Ce script illustre un point intéressant même sans Error.isError disponible : la ligne erreurDunAutreRoyaume instanceof Error : false montre bien le piège réel que Error.isError est censé résoudre — l'objet est pourtant, conceptuellement, une vraie erreur.

    16.5. script [04-map-weakmap-getOrInsert]

    [Map.prototype.getOrInsert]/[getOrInsertComputed] répondent à un besoin très fréquent : « si la clé existe déjà, prends sa valeur ; sinon, crée une valeur par défaut et mémorise-la », en une seule ligne plutôt qu'un if (!map.has(clé)) { map.set(...) } verbeux. Le même principe existe pour WeakMap.

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU ECMAScript 2026] Map.prototype.getOrInsert / getOrInsertComputed
  4  // ========================================================================
  5  // [Node 26+ - officiellement listé dans les notes de version de node 26.0.0 :
  6  // voir https://nodejs.org/en/blog/release/v26.0.0 - donc normalement déjà
  7  // disponible si tu es sur node 26. Si ce n'est pas le cas, vérifie avec :
  8  //   node -e "console.log(typeof Map.prototype.getOrInsert)"
  9  // voir aussi ecmascript-2026/README.md pour le cas des autres nouveautés de
 10  // ce dossier, qui n'ont pas toutes le même niveau de disponibilité]
 11  
 12  // un besoin très fréquent : "si la clé existe déjà dans la Map, prends sa valeur ;
 13  // sinon, crée une valeur par défaut, mémorise-la, puis utilise-la"
 14  
 15  // ------------------------------------------------------------------------
 16  // 1) l'ancienne façon : if/has() puis set() - verbeux, et facile à mal écrire
 17  // ------------------------------------------------------------------------
 18  const inscriptionsParAtelier = new Map<string, string[]>();
 19  
 20  function inscrireAncienneFaçon(atelier: string, participant: string): void {
 21    if (!inscriptionsParAtelier.has(atelier)) {
 22      inscriptionsParAtelier.set(atelier, []);
 23    }
 24    inscriptionsParAtelier.get(atelier)!.push(participant);
 25    // le "!" est nécessaire ici : TypeScript ne peut pas savoir, à cet endroit précis,
 26    // que le .get() qui suit un .set() juste avant réussira forcément
 27  }
 28  inscrireAncienneFaçon("cuisine", "Ana");
 29  inscrireAncienneFaçon("cuisine", "Léo");
 30  console.log("avec l'ancienne façon :", inscriptionsParAtelier);
 31  
 32  if (typeof Map.prototype.getOrInsert !== "function") {
 33    console.log("Map.prototype.getOrInsert n'est pas disponible sur ce moteur JavaScript",
 34      "(voir le commentaire en tête de ce fichier) - seule la partie 1) ci-dessus a pu s'exécuter");
 35  } else {
 36    // ------------------------------------------------------------------------
 37    // 2) Map.prototype.getOrInsert() : la même chose, en une seule ligne
 38    // ------------------------------------------------------------------------
 39    const inscriptions2 = new Map<string, string[]>();
 40  
 41    const inscrire = (atelier: string, participant: string): void => {
 42      // rend le tableau existant pour [atelier], ou l'initialise à [] s'il n'existe pas encore
 43      inscriptions2.getOrInsert(atelier, []).push(participant);
 44    }
 45    inscrire("poterie", "Nora");
 46    inscrire("poterie", "Théo");
 47    console.log("avec getOrInsert :", inscriptions2);
 48  
 49    // ------------------------------------------------------------------------
 50    // 3) getOrInsertComputed() : la valeur par défaut n'est calculée QUE si besoin
 51    // ------------------------------------------------------------------------
 52    // avec getOrInsert(clé, valeur), la [valeur] par défaut est TOUJOURS évaluée,
 53    // même quand la clé existe déjà et qu'on n'en a pas besoin (ici ce n'est pas
 54    // grave pour un tableau vide [], mais ça peut l'être pour un calcul coûteux)
 55    const compteurs = new Map<string, number>();
 56  
 57    const incrémenter = (clé: string): void => {
 58      // le callback n'est appelé QUE si la clé n'existe pas encore dans la Map
 59      const valeur = compteurs.getOrInsertComputed(clé, () => {
 60        console.log(`[calcul de la valeur initiale pour "${clé}"]`);
 61        return 0;
 62      });
 63      compteurs.set(clé, valeur + 1);
 64    }
 65    incrémenter("visites");
 66    incrémenter("visites"); // ici, le callback ne sera PAS réexécuté
 67    incrémenter("clics");
 68    console.log("compteurs =", compteurs);
 69  
 70    // ------------------------------------------------------------------------
 71    // 4) WeakMap.prototype.getOrInsert / getOrInsertComputed : même principe,
 72    // pour associer des données supplémentaires à des objets sans empêcher leur
 73    // nettoyage par le ramasse-miettes (garbage collector)
 74    // ------------------------------------------------------------------------
 75    interface Métadonnées {
 76      vues: number;
 77    }
 78    const métadonnéesParObjet = new WeakMap<object, Métadonnées>();
 79  
 80    const enregistrerUneVue = (objet: object): void => {
 81      const métadonnées = métadonnéesParObjet.getOrInsertComputed(objet, () => ({ vues: 0 }));
 82      métadonnées.vues++;
 83    }
 84    const article = { titre: "Découverte du WeakMap" };
 85    enregistrerUneVue(article);
 86    enregistrerUneVue(article);
 87    console.log("métadonnées de l'article =", métadonnéesParObjet.get(article));
 88  }

    npx tsx ecmascript-2026/04-map-weakmap-getOrInsert.ts

    Résultat de l'exécution :

      1  avec l'ancienne façon : Map(1) { 'cuisine' => [ 'Ana', 'Léo' ] }
  2  Map.prototype.getOrInsert n'est pas disponible sur ce moteur JavaScript (voir le commentaire en tête de ce fichier) - seule la partie 1) ci-dessus a pu s'exécuter

    16.6. script [05-uint8array-base64-hex]

    Uint8Array (un tableau typé d'octets bruts) reçoit de nouvelles méthodes de conversion vers/depuis le base64 et l'hexadécimal — des formats couramment utilisés pour transmettre des données binaires en JSON ou en URL, sans dépendre d'un package tiers :

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU ECMAScript 2026] Uint8Array : conversion base64 et hexadécimal
  4  // ========================================================================
  5  // [statut de disponibilité à vérifier toi-même : voir ecmascript-2026/README.md.
  6  // Certaines nouveautés d'ES2026 (comme Math.sumPrecise) sont encore absentes
  7  // de V8 malgré le Stage 4 obtenu - il n'est pas exclu que ce soit aussi le cas
  8  // ici. Vérifie avec : node -e "console.log(typeof Uint8Array.prototype.toBase64)"]
  9  
 10  // [Uint8Array] est un tableau typé qui stocke des octets bruts (valeurs 0-255) -
 11  // par exemple le contenu d'un fichier, une image, ou une donnée reçue par le réseau
 12  
 13  // avant 2026, pour encoder ces octets en base64 (le format utilisé par exemple
 14  // dans les URLs de données "data:", ou pour transmettre du binaire en JSON),
 15  // il fallait passer par des fonctions détournées ou des packages tiers (buffer côté node,
 16  // btoa/atob côté navigateur - imparfaits et pas conçus pour ça à l'origine)
 17  
 18  const octets = new Uint8Array([72, 101, 108, 108, 111]); // "Hello" en codes ASCII
 19  
 20  if (typeof octets.toBase64 !== "function") {
 21    console.log("Uint8Array.prototype.toBase64 n'est pas disponible sur ce moteur JavaScript",
 22      "(voir le commentaire en tête de ce fichier)");
 23  } else {
 24    // ------------------------------------------------------------------------
 25    // 1) encodage en base64
 26    // ------------------------------------------------------------------------
 27    const enBase64 = octets.toBase64();
 28    console.log("octets en base64 =", enBase64);
 29  
 30    // décodage : reconstruire un Uint8Array à partir d'une chaîne base64
 31    const octetsRetrouvés = Uint8Array.fromBase64(enBase64);
 32    console.log("octets retrouvés =", octetsRetrouvés);
 33    console.log("identiques à l'original :", octets.toString() === octetsRetrouvés.toString());
 34  
 35    // ------------------------------------------------------------------------
 36    // 2) encodage en hexadécimal
 37    // ------------------------------------------------------------------------
 38    const enHexadécimal = octets.toHex();
 39    console.log("octets en hexadécimal =", enHexadécimal);
 40  
 41    const octetsDepuisHex = Uint8Array.fromHex(enHexadécimal);
 42    console.log("octets depuis hex =", octetsDepuisHex);
 43  
 44    // ------------------------------------------------------------------------
 45    // 3) remplir un Uint8Array existant, à partir d'un offset donné
 46    // ------------------------------------------------------------------------
 47    // utile pour assembler plusieurs morceaux dans un même buffer, sans allocations
 48    // intermédiaires
 49    const buffer = new Uint8Array(10);
 50    const résultatEcriture = buffer.setFromHex("48656c6c6f"); // "Hello" en hexadécimal
 51    console.log("buffer après setFromHex =", buffer);
 52    console.log("caractères lus / écrits =", résultatEcriture);
 53  }
 54  
 55  // ------------------------------------------------------------------------
 56  // pourquoi c'est utile : transmission de données binaires dans des formats texte
 57  // (JSON, URL, headers HTTP...), sans dépendre d'un package tiers ou de bricolages
 58  // ------------------------------------------------------------------------

    npx tsx ecmascript-2026/05-uint8array-base64-hex.ts

    Résultat de l'exécution :

      1  Uint8Array.prototype.toBase64 n'est pas disponible sur ce moteur JavaScript (voir le commentaire en tête de ce fichier)

    16.7. script [06-json-rawJSON-et-reviver]

    Ce dernier script se distingue des précédents : [JSON.rawJSON]/[isRawJSON], ainsi que le nouveau paramètre context du reviver de JSON.parse, fonctionnent déjà dans l'environnement de préparation de ce cours (Node 22) :

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU ECMAScript 2026] JSON.rawJSON / JSON.isRawJSON, et le contexte du reviver
  4  // ========================================================================
  5  // [ces deux nouveautés fonctionnent déjà avec node 22, contrairement aux autres
  6  // scripts de ce dossier qui nécessitent node 24 - voir ecmascript-2026/README.md]
  7  
  8  // ------------------------------------------------------------------------
  9  // 1) le problème : JSON.stringify perd de la précision sur les grands entiers
 10  // ------------------------------------------------------------------------
 11  // un nombre JavaScript classique (type [number]) ne peut pas représenter
 12  // exactement les entiers au-delà de Number.MAX_SAFE_INTEGER (cf. bases/bases-09.ts)
 13  // beaucoup d'API (bases de données, réseaux sociaux, ...) envoient pourtant des
 14  // identifiants numériques à 17-19 chiffres dans leur JSON
 15  const identifiantColonneBaseDeDonnées = "9007199254740993123"; // trop grand pour un [number]
 16  
 17  interface Enregistrement {
 18    id: unknown; // unknown ici car ce sera soit un RawJSON, soit une valeur normale
 19    nom: string;
 20  }
 21  
 22  // ------------------------------------------------------------------------
 23  // 2) JSON.rawJSON() : insère un nombre "brut" dans un JSON.stringify,
 24  //    sans jamais le faire passer par le type [number] (donc sans perte de précision)
 25  // ------------------------------------------------------------------------
 26  const enregistrement: Enregistrement = {
 27    id: JSON.rawJSON(identifiantColonneBaseDeDonnées),
 28    nom: "capteur-température-3"
 29  };
 30  
 31  const texteJSON = JSON.stringify(enregistrement);
 32  console.log("texteJSON =", texteJSON);
 33  // l'identifiant apparaît tel quel dans le texte produit, chiffre pour chiffre,
 34  // alors qu'un id: Number(identifiantColonneBaseDeDonnées) aurait été arrondi
 35  
 36  // JSON.isRawJSON() permet de vérifier si une valeur a été créée par JSON.rawJSON
 37  console.log("JSON.isRawJSON(enregistrement.id) =", JSON.isRawJSON(enregistrement.id));
 38  
 39  // ------------------------------------------------------------------------
 40  // 3) le reviver de JSON.parse reçoit maintenant un 3ième paramètre [context]
 41  // ------------------------------------------------------------------------
 42  // avant 2026, le reviver ne recevait que (clé, valeur) : impossible de savoir
 43  // quel était le texte JSON EXACT d'où venait cette valeur (utile justement
 44  // pour récupérer un grand nombre sans perte, en le gardant sous forme de texte)
 45  const objetRelu = JSON.parse(texteJSON, (clé, valeur, context) => {
 46    // [context.source] donne le texte JSON brut correspondant à cette valeur,
 47    // avant toute conversion en type JavaScript - undefined pour les objets/tableaux
 48    if (context?.source !== undefined) {
 49      console.log(`clé="${clé}", valeur convertie=${valeur}, texte JSON d'origine="${context.source}"`);
 50    }
 51    return valeur;
 52  });
 53  console.log("objetRelu =", objetRelu);
    • [JSON.rawJSON(texte)] insère un nombre « brut » dans JSON.stringify, sans jamais le faire passer par le type number — utile pour les très grands identifiants numériques (au-delà de Number.MAX_SAFE_INTEGER, voir bases-09), qui perdraient sinon en précision ;
    • le 3ᵉ paramètre context du reviver donne accès, via context.source, au texte JSON brut de la valeur en cours de traitement — avant toute conversion en type JavaScript.

    Résultat de l'exécution :

      1  texteJSON = {"id":9007199254740993123,"nom":"capteur-température-3"}
  2  JSON.isRawJSON(enregistrement.id) = true
  3  clé="id", valeur convertie=9007199254740993000, texte JSON d'origine="9007199254740993123"
  4  clé="nom", valeur convertie=capteur-température-3, texte JSON d'origine=""capteur-température-3""
  5  objetRelu = { id: 9007199254740993000, nom: 'capteur-température-3' }

    On observe très concrètement l'intérêt de JSON.rawJSON : le texte JSON produit conserve l'identifiant chiffre pour chiffre (9007199254740993123), alors qu'un simple id: Number(...) l'aurait arrondi — comme le montre justement la valeur relue par JSON.parse (9007199254740993000), qui, elle, est bien passée par le type number et a perdu en précision.
