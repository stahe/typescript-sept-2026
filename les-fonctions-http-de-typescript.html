    12. Les fonctions HTTP de TypeScript

    Nous présentons ici deux façons de faire des requêtes HTTP en TypeScript : la fonction [fetch], native depuis Node 18, et la bibliothèque tierce [axios]. Les scripts de ce chapitre se trouvent dans le dossier [http] du projet.

    12.1. Choix des outils HTTP

    En 2019, fetch n'était pas encore implémentée par node.js, et le document original recommandait le package node-fetch. Depuis Node 18 (2022), [fetch] est une fonction globale native, standardisée par le WHATWG Fetch standard — plus besoin de l'importer.

    [axios] reste néanmoins une bibliothèque intéressante : compatible aussi bien avec node.js qu'avec les navigateurs, elle offre une API un peu plus riche (intercepteurs, sérialisation JSON automatique, gestion d'erreurs uniformisée). Nous présentons les deux, avec le même exemple, pour montrer que la démarche de codage est analogue.

    12.2. Le serveur de calcul de l'impôt

    Ce chapitre, comme les suivants, fait référence au serveur de calcul de l'impôt PHP construit dans le cours « Introduction au langage PHP7 par l'exemple ». Son installation (Laragon, Netbeans, configuration de config.json) n'a pas changé et reste décrite dans ce cours PHP — nous n'y revenons pas ici.

    Rappel de l'API exposée par ce serveur :

    • [init-session] — GET main.php?action=init-session&type=x — fixe le type (json, xml, html) des réponses souhaitées ; peut être émise à tout moment ;
    • [authentifier-utilisateur] — POST main.php?action=authentifier-utilisateur, paramètres postés [user, password] — autorise ou non la connexion ;
    • [calculer-impot] — POST main.php?action=calculer-impot, paramètres postés [marié, enfants, salaire] — fait une simulation de calcul d'impôt ;
    • [lister-simulations] — GET main.php?action=lister-simulations — liste les simulations faites depuis le début de la session ;
    • [supprimer-simulation] — GET main.php?action=supprimer-simulation&numéro=x — supprime une simulation de la liste ;
    • [fin-session] — termine la session de simulations.
    Important : les scripts de ce chapitre supposent que ce serveur PHP tourne en local, sur http://localhost/php7/scripts-web/impots/version-14/. Dans l'environnement où ce document a été préparé, ce serveur PHP n'est pas disponible : les exécutions ci-dessous montrent donc systématiquement le cas « serveur non lancé » (erreur de connexion), qui est un résultat réel et vérifié. Le comportement en cas de succès, lui, est décrit à partir du code et des commentaires, mais n'a pas pu être vérifié par une exécution réelle dans cet environnement.

    12.3. script [fetch-01]

    Ce script utilise [fetch] pour initialiser une session JSON avec le serveur de calcul d'impôt :

      1  'use strict';
  2  
  3  // [mise à jour 2026] en 2019, il fallait installer le package [node-fetch] pour disposer
  4  // de la fonction [fetch] côté node. Depuis Node 18 (2022), [fetch] est une fonction
  5  // globale native, standardisée par le "WHATWG Fetch standard" : plus besoin de l'importer.
  6  // imports
  7  import qs from 'qs';
  8  import { sprintf } from 'sprintf-js';
  9  import moment from 'moment';
 10  
 11  
 12  // URL de base du serveur de calcul d'impôt
 13  const baseUrl: string = 'http://localhost/php7/scripts-web/impots/version-14/main.php?';
 14  // init session
 15  async function initSession(): Promise<any> {
 16    // [mise à jour 2026] le [fetch] natif ne connaît pas l'option [timeout].
 17    // pour limiter la durée d'attente, on lui fournit un [signal] produit par
 18    // [AbortSignal.timeout(ms)] (disponible depuis Node 17.3) : passé ce délai,
 19    // la requête est automatiquement annulée et [fetch] lève une erreur.
 20    const options: RequestInit = {
 21      method: "GET",
 22      signal: AbortSignal.timeout(2000)
 23    };
 24    // exécution de la requête HTTP [get /main.php?action=init-session&type=json]
 25    let débutFetch: moment.Moment | undefined;
 26    try {
 27      // requête asynchrone - [fetch] rend une promesse
 28      débutFetch = moment(Date.now());
 29      const response = await fetch(baseUrl + qs.stringify({
 30        action: 'init-session',
 31        type: 'x'
 32      }), options);
 33      // [response] est l'ensemble de la réponse HTTP du serveur (entêtes HTTP + réponse elle-même)
 34      // on affiche cette réponse pour voir sa structure
 35      console.log(sprintf("réponse fetch formatée en json,=%j, %s", response, heure(débutFetch)));
 36      console.log("réponse fetch en javascript=", response);
 37      // on peut avoir aux entêtes HTTP
 38      console.log("entêtes de la réponse=", response.headers);
 39      // si réponse de type application / json, la réponse json du serveur est obtenue avec la fonction asynchrone [response.json()]
 40      // dans ce cas le code appelant obtient un objet [Promise]
 41      // [await] permet d'obtenir la réponse [json] du serveur plutôt que sa promesse
 42      const débutJson = moment(Date.now());
 43      const objet = await response.json();
 44      console.log(sprintf("réponse json=%j, type=%s, %s", objet, typeof (objet), heure(débutJson)));
 45      return objet;
 46      // si réponse de type text / plain, la réponse texte du serveur est obtenue avec [response.text()]
 47      // dans ce cas le code appelant obtient un objet [Promise]
 48      // [await] permet d'obtenir la réponse [texte] du serveur plutôt que sa promesse
 49      // const text = await response.text();
 50      // console.log("réponse texte=", text);
 51      // return text;
 52    } catch (error: any) {
 53      // on est là parce que le serveur a envoyé un code d'erreur [404 Not Found, ...] accompagné d'un corps vide - on affiche l'erreur pour voir sa structure
 54      // ou bien parce que le client [fetch] a lancé une exception (réseau inaccesible, ...)
 55      // on affiche la structure de l'erreur
 56      console.log(sprintf("error fetch en json=%j, %s", error, heure(débutFetch)));
 57      console.log("error fetch en javascript=", typeof (error), error);
 58      // on lance le msg d'erreur reçu
 59      throw error.message;
 60    }
 61  }
 62  
 63  // la fonction main exécute la fonction asynchrone [initSession]
 64  async function main(): Promise<void> {
 65    try {
 66      console.log("requête HTTP vers le serveur en cours ---------------------------------------------");
 67      const response = await initSession();
 68      console.log("succès ---------------------------------------------");
 69      console.log("réponse=", response, typeof (response))
 70    } catch (error) {
 71      console.log("erreur ---------------------------------------------");
 72      console.log("erreur=", error, typeof (error));
 73    }
 74  }
 75  
 76  // test
 77  main();
 78  
 79  // utilitaire d'affichage heure et durée
 80  function heure(début?: moment.Moment): string {
 81    // heure du moment courant
 82    const now = moment(Date.now());
 83    // formatage heure
 84    let result = "heure=" + now.format("HH:mm:ss:SSS");
 85    // faut-il calculer une durée ?
 86    if (début) {
 87      const durée = now.valueOf() - début.valueOf();
 88      const milliseconds = durée % 1000;
 89      const seconds = Math.floor(durée / 1000);
 90      // formatage heure + durée
 91      result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
 92    }
 93    // résultat
 94    return result;
 95  }
    • lignes 3-5 : [mise à jour 2026] — commentaire signalant que fetch est désormais natif, contrairement à 2019 ;
    • ligne 18 : AbortSignal.timeout(2000) — remplace l'option timeout de node-fetch (qui n'existe pas sur fetch natif) : au-delà de 2 secondes, la requête est automatiquement annulée ;
    • ligne 27 : fetch(URL, options) — la syntaxe reste celle du fetch standard : une URL, et un objet d'options (méthode, signal d'annulation...) ;
    • ligne 38 : await response.json() — extrait le corps JSON de la réponse ; c'est une opération elle-même asynchrone (response peut être un flux en cours de réception) ;
    • ligne 50 : fetch ne lance une exception que si la requête HTTP n'a pu aboutir (réseau inaccessible, timeout...). Si une réponse est reçue, même avec un code d'erreur (400, 500...), fetch ne lance pas d'exception : la réponse est disponible normalement, ligne 38.

    12.5. script [axios-01]

    Même exemple, avec [axios] :

      1  'use strict';
  2  import axios, { AxiosInstance, AxiosRequestConfig } from 'axios';
  3  
  4  // configuration par défaut d'axios
  5  axios.defaults.timeout = 2000;
  6  axios.defaults.baseURL = 'http://localhost/php7/scripts-web/impots/version-14';
  7  
  8  // init session
  9  async function initSession(axios: AxiosInstance): Promise<any> {
 10    // options de la requête HHTP [get /main.php?action=init-session&type=json]
 11    const options: AxiosRequestConfig = {
 12      // [mise à jour TypeScript] axios.request() n'accepte, côté typage, qu'un seul
 13      // argument de configuration : l'URL doit donc figurer dans [options.url]
 14      // plutôt qu'en 1er paramètre séparé de request()
 15      url: 'main.php',
 16      method: "GET",
 17      // paramètres de l'URL
 18      params: {
 19        action: 'init-session',
 20        type: 'x'
 21      }
 22    };
 23    // exécution de la requête HTTP [get /main.php?action=init-session&type=json]
 24    try {
 25      // requête asynchrone
 26      const response = await axios.request(options);
 27      // response est l'ensemble de la réponse HTTP du serveur (entêtes HTTP + réponse elle-même)
 28      // on affiche cette réponse pour voir sa structure
 29      console.log("réponse axios=", response);
 30      // la réponse du serveur est dans [response.data]
 31      return response.data;
 32    } catch (error: any) {
 33      // on est là parce que le serveur a envoyé un code d'erreur [404 Not Found, 500 Internal Server Error, ...]
 34      // le paramètre [error] est une instance d'exception - elle peut avoir diverses formes
 35      // on l'affiche pour voir sa structure
 36      console.log("axios error=", typeof (error), error);
 37      if (error.response) {
 38        // le serveur a signalé une erreur dans le statut HTTP mais il a aussi envoyé une réponse
 39        // alors celle-ci est trouvée dans [error.response.data]
 40        // on sait que le serveur envoie des réponses jSON de structure {action, état, réponse}
 41        // et qu'en cas d'erreur, le msg d'erreur est dans [réponse]
 42        return error.response.data;
 43      } else {
 44        // on lance l'erreur
 45        throw error;
 46      }
 47    }
 48  }
 49  
 50  // la fonction main exécute la fonction asynchrone [initSession]
 51  async function main(): Promise<void> {
 52    try {
 53      console.log("requête HTTP vers le serveur en cours ---------------------------------------------");
 54      const response = await initSession(axios);
 55      console.log("succès ---------------------------------------------");
 56      console.log("réponse=", response, typeof (response))
 57    } catch (error: any) {
 58      console.log("erreur ---------------------------------------------");
 59      console.log("erreur=", error.message);
 60    }
 61  }
 62  
 63  // test
 64  main();
    • ligne 24 : axios.request(options) — contrairement à fetch, l'URL et les options sont regroupées dans un seul objet de configuration ;
    • ligne 33 : error.response — si le serveur a répondu (même avec un code d'erreur), axios place cette réponse dans error.response, accessible dans le catch — contrairement à fetch, axios lance systématiquement une exception dès que le code HTTP n'est pas un succès (2xx) ;
    • ligne 26 : la réponse réussie est dans response.data — axios fait automatiquement l'extraction JSON, pas besoin d'un await response.json() séparé comme avec fetch.

    12.6. script [axios-03] — authentification

    Ce script enchaîne deux requêtes : init-session, puis authentifier-utilisateur en [POST], avec un corps encodé par la bibliothèque [qs] :

      1  'use strict';
  2  import axios, { AxiosInstance, AxiosRequestConfig } from 'axios';
  3  import qs from 'qs'
  4  
  5  // configuration axios
  6  axios.defaults.timeout = 2000;
  7  axios.defaults.baseURL = 'http://localhost/php7/scripts-web/impots/version-14';
  8  
  9  
 10  // init session
 11  async function initSession(axios: AxiosInstance): Promise<any> {
 12    // options de la requête HHTP [get /main.php?action=init-session&type=json]
 13    const options: AxiosRequestConfig = {
 14      // [mise à jour TypeScript] URL incluse dans [options.url] (axios.request() typé n'accepte qu'un seul argument)
 15      url: 'main.php',
 16      method: "GET",
 17      // paramètres de l'URL
 18      params: {
 19        action: 'init-session',
 20        type: 'json'
 21      }
 22    };
 23    try {
 24      // exécution de la requête HTTP [get /main.php?action=init-session&type=json]
 25      const response = await axios.request(options);
 26      // la réponse du serveur est dans [response.data]
 27      return response.data;
 28    } catch (error: any) {
 29      // réponse du serveur
 30      if (error.response) {
 31        // la réponse jSON est dans [error.response.data]
 32        return error.response.data;
 33      } else {
 34        // on relance l'erreur
 35        throw error;
 36      }
 37    }
 38  }
 39  
 40  async function authentifierUtilisateur(axios: AxiosInstance, user: string, password: string): Promise<any> {
 41    // options de la requête HHTP [post /main.php?action=authentifier-utilisateur]
 42    const options: AxiosRequestConfig = {
 43      // [mise à jour TypeScript] URL incluse dans [options.url]
 44      url: 'main.php',
 45      method: "POST",
 46      headers: {
 47        'Content-type': 'application/x-www-form-urlencoded',
 48      },
 49      // corps du POST
 50      data: qs.stringify({
 51        user: user,
 52        password: password
 53      }),
 54      // paramètres de l'URL
 55      params: {
 56        action: 'authentifier-utilisateur'
 57      }
 58    };
 59    try {
 60      // exécution de la requête HTTP [get /main.php?action=init-session&type=json]
 61      const response = await axios.request(options);
 62      // la réponse du serveur est dans [response.data]
 63      return response.data;
 64    } catch (error: any) {
 65      // réponse du serveur
 66      if (error.response) {
 67        // la réponse jSON est dans [error.response.data]
 68        return error.response.data;
 69      } else {
 70        // on relance l'erreur
 71        throw error;
 72      }
 73    }
 74  }
 75  
 76  // la fonction main exécute les fonctions asynchrones une par une
 77  async function main(): Promise<void> {
 78    try {
 79      // init-session
 80      console.log("action init-session en cours ---------------------------------------------");
 81      const response1 = await initSession(axios);
 82      console.log("succès ---------------------------------------------");
 83      console.log("réponse=", response1);
 84      // authentifier-utilisateur
 85      console.log("action authentifier-utilisateur en cours ---------------------------------------------");
 86      const response2 = await authentifierUtilisateur(axios, 'admin', 'admin');
 87      console.log("succès ---------------------------------------------");
 88      console.log("réponse=", response2)
 89    } catch (error) {
 90      console.log("erreur ---------------------------------------------");
 91      console.log("erreur=", error);
 92    }
 93  }
 94  
 95  // test
 96  main();
    • lignes 39-53 : la requête POST envoie ses paramètres (user, password) encodés en application/x-www-form-urlencoded, via qs.stringify(...) dans options.data ;
    • les deux fonctions sont exécutées séquentiellement dans main (await l'une après l'autre) : la seconde ne peut avoir de sens que si la première a réussi, puisqu'elle dépend du cookie de session établi par init-session.

    12.7. script [axios-04] — gestion du cookie de session

    12.8. script [fetch-03] — annulation de requêtes

    [NOUVEAU depuis 2019] Ce script illustre deux usages du mécanisme d'annulation des requêtes fetch, disponible nativement depuis Node 18 :

      1  'use strict';
  2  // ========================================================================
  3  // [NOUVEAU depuis 2019] fetch natif + annulation d'une requête HTTP
  4  // ========================================================================
  5  
  6  // [fetch] est global depuis Node 18 : plus besoin du package [node-fetch]
  7  // utilisé en 2019 dans fetch-01.js/fetch-02.js (voir les commentaires [mise à jour 2026]
  8  // ajoutés dans ces deux fichiers)
  9  
 10  // URL de base du serveur de calcul d'impôt (voir http/README.md)
 11  // comme pour axios-01.js, ce script suppose que le serveur PHP du cours tourne
 12  // en local : sans lui, les requêtes échouent avec "fetch failed", ce qui est normal
 13  const baseUrl: string = 'http://localhost/php7/scripts-web/impots/version-14/main.php';
 14  
 15  // exemple 1 : requête avec délai maximum grâce à AbortSignal.timeout()
 16  async function requêteAvecDélaiMaximum(): Promise<void> {
 17    console.log("--- requête avec AbortSignal.timeout ---");
 18    try {
 19      const response = await fetch(baseUrl + '?action=init-session&type=json', {
 20        // au-delà de 2 secondes, la requête est annulée automatiquement
 21        signal: AbortSignal.timeout(2000)
 22      });
 23      const données = await response.json();
 24      console.log("réponse =", données);
 25    } catch (erreur: any) {
 26      // si le serveur n'existe pas (cas probable dans cet exercice), ou si le délai est dépassé,
 27      // [erreur.name] vaut "TimeoutError" ou "AbortError" selon le cas
 28      console.log("erreur.name =", erreur.name, ", message =", erreur.message);
 29    }
 30  }
 31  
 32  // exemple 2 : annulation manuelle d'une requête, par exemple parce que
 33  // l'utilisateur a changé d'avis (ex : il retape dans un champ de recherche)
 34  async function requêteAnnulableManuellement(): Promise<void> {
 35    console.log("--- requête annulée manuellement ---");
 36    const contrôleur = new AbortController();
 37  
 38    // on programme une annulation "métier" au bout de 500 ms
 39    // (dans une vraie application, ce serait par exemple un clic sur un bouton "annuler")
 40    setTimeout(() => {
 41      console.log("annulation manuelle déclenchée");
 42      contrôleur.abort();
 43    }, 500);
 44  
 45    try {
 46      const response = await fetch(baseUrl + '?action=init-session&type=json', {
 47        signal: contrôleur.signal
 48      });
 49      const données = await response.json();
 50      console.log("réponse =", données);
 51    } catch (erreur: any) {
 52      console.log("erreur.name =", erreur.name, ", message =", erreur.message);
 53    }
 54  }
 55  
 56  async function main(): Promise<void> {
 57    await requêteAvecDélaiMaximum();
 58    await requêteAnnulableManuellement();
 59  }
 60  
 61  main();
    • [AbortSignal.timeout(ms)] : annule automatiquement la requête si elle dépasse le délai donné — pattern déjà vu au script fetch-01 ;
    • [AbortController] : permet une annulation manuelle, déclenchée par n'importe quel événement applicatif (ici un setTimeout simulant, par exemple, un clic sur un bouton « Annuler », ou une nouvelle frappe dans un champ de recherche qui invalide la requête précédente).

    Résultat de l'exécution :

      1  --- requête avec AbortSignal.timeout ---
  2  erreur.name = TypeError , message = fetch failed
  3  --- requête annulée manuellement ---
  4  erreur.name = TypeError , message = fetch failed
  5  annulation manuelle déclenchée

    Le serveur n'étant pas disponible ici, l'erreur fetch failed (connexion refusée) apparaît avant même que les mécanismes d'annulation n'aient l'occasion de se déclencher — sur un serveur disponible mais lent, on obtiendrait plutôt erreur.name = TimeoutError ou AbortError, comme l'indique le commentaire du script.
